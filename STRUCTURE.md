# Структура проекта — Конфигуратор мебели

Коротко, для ориентира. Подробности — читаю сам по коду, когда нужно. **Обновляю при изменении структуры**, держу так же коротко.

Статический сайт без сборки: `index.html` + `css/style.css` + JS-модули в браузере.

Эта папка (`Config/config`) — только программа и git-репозиторий; рабочие материалы — уровнем
выше в `Config/` (Задания, Выгрузки, Бэкапы, Хостинг, Приложения, Ассортимент — см. `../CLAUDE.md`).

## Основные блоки

- **`js/core/`** — всё общее, не привязанное к типу мебели: 3D-сцена и камера, общее состояние проекта, UI-панель справа, перетаскивание элементов мышкой, размерные линии, заказ/пресеты, окно «Редактировать дверь» (doorEditor), печать сметы с предпросмотром (print), защита полей от автозаполнения браузера (autofillGuard), комната-визуализация вокруг шкафа (room — полупрозрачные стены, цвет, позиция шкафа).
- **`js/types/`** — по файлу на тип мебели (шкаф-купе, распашной, комод, стол и т.д.). Шкаф-купе — основной, самый проработанный тип. Готовые (не «в разработке») типы — белый список `READY_TYPES` в `tabs.js` (сейчас шкаф-купе + «Двери купе»). «Двери купе» (`sliding-doors.js`) — самостоятельное изделие: двери + выравниватели ЛДСП по периметру (нет/планка/короб). Дверной ряд у шкафа и дверей-купе общий — `buildDoorRow` (`wardrobe-geometry.js`); расчёт пролёта/периметра — `effectiveDoorSpan` (`wardrobe-sizing.js`, тип-осведомлённый).
- **Наполнение шкафа-купе** (полки/ящики/штанга/сетка/корзины/вешало) — самая объёмная часть, разложена на 4 файла по смыслу: «сколько места доступно» / «что где стоит и не пересекается» / «как это выглядит в 3D» / общие константы.
- **`data/materials.json`** — каталог материалов, цветов и цен; `data/textures/` — картинки материалов (кладёт `scripts/textures_import.py`, имя файла хранится у материала в поле `texture`). Показ в 3D — `js/core/textures.js`: тайлинг 500 мм на «плитку» через развёртку UV панели, один объект текстуры на весь шкаф, загрузка только используемых и выгрузка неиспользуемых.
- **Личный кабинет/логин** (auth/cabinet/admin) — отдельная, независимая фича, разрабатывается параллельно, к 3D-конфигуратору не относится.
- **SaaS-мультитенантность** — вкладка «Люди» (`users.js`, модалка) для админа компании: список менеджеров + создать/править/пароль/блок через Edge Function; загрузчик каталога компании — в `main.js` (`loadMaterials`). Схема/функция/супер-админка — в `supabase/` и `admin.html`. Стратегия — `Config/SAAS-PLAN.md` (Яндекс).

## Прочее

`DEVLOG.md` — журнал сессий. `CLAUDE.md` — инструкции для Claude. Знания о системах купе (формулы размеров дверей/профилей/наполнения по каталогам производителей, декоры, оригиналы каталогов) — ВНЕ этого репозитория, в базе `C:\KB_KUPE` (`github.com/kshromin/kupe-kb`, приватный), подключается через `/add-dir`; там же скиллы `kupe-kb` и `door-sizing`. Подробнее — в `CLAUDE.md`. `scripts/dev-server.py` — локальный сервер для превью без кэша. `DATA-SCHEMA.md` — контракт данных ассортимента (единая позиционная модель, v0.2; под будущие приложения/калькулятор). `scripts/catalog_export.py` + `catalog_import.py` — выгрузка/загрузка ассортимента в Excel по этой схеме (стабильные `_key`, ручная цена = «вручную», валидация с бэкапом); заменяют устаревшие `prices_export.py`/`prices_import.py`, несовместимые со структурой профилей после сессии 56. `CNAME` — привязка домена GitHub Pages (`config.khrom-in.ru`). `assets/` — статические картинки сайта (напр. `khrom-logo.png` — лого разработчика в углу экрана, `#devLogo`); `assets/profiles/*.webp` — фото профилей купе для селектора «ПРОФИЛЬ» (сжаты из каталога, без размеров). `SUPABASE-SETUP.md` — исходная схема БД/RLS; `supabase/` — серверная часть SaaS: `saas-01-schema.sql` (миграция companies/company_id/RLS, вручную в SQL Editor), `functions/create-company-user/` (Edge Function создания пользователей на service_role — с проверкой прав и лимита `max_users`). `admin.html` — отдельная страница супер-админа (управление компаниями: список, создать компанию + её админа через Edge Function, блокировка), вход только для `is_admin`. Стратегия SaaS/хостинга — в `Config/SAAS-PLAN.md` на Яндексе (вне репозитория).
