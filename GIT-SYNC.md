# Синхронизация между компьютерами — что делать

Раньше код между двумя компьютерами расходился через Yandex.Disk (копировались все файлы, включая `.git`). Это ненадёжно: `.git` — не обычные файлы, а база данных git, файловая синхронизация может её испортить при не вовремя пойманном моменте. Поэтому теперь код синхронизируется через GitHub, а Yandex.Disk синхронизирует только сами файлы проекта (это происходит само собой, ничего для этого делать не нужно).

**Схема с сессии 45 (25.07.2026): код вынесен ОТДЕЛЬНОЙ папкой ВНЕ Яндекс.Диска** — `config_comp`
на компе, `config_nout` на ноуте. Так Яндекс код вообще не синхронизирует (и не может испортить
`.git`), обмен между машинами — только через GitHub. Материалы (Задания, Выгрузки, Бэкапы,
Ассортимент) остаются на Яндекс.Диске в папке `Config` и синхронизируются им как обычно. Из чата
папку материалов подключают через `/add-dir`. Все git-команды — из папки кода.

Это заменяет прежнюю схему «код в `Config\config` внутри Яндекса + git-база вынесена через
`--separate-git-dir`»: раз вся папка кода теперь вне Яндекса, отдельная git-база не нужна —
обычный клон с `.git` внутри безопасен. Разовая настройка перехода — сразу ниже; старые разделы
про `--separate-git-dir` и аварийную починку оставлены как справочник на случай отката.

## Разовая настройка: вынести код из Яндекса (на КАЖДОЙ машине)

Выполняется локально на компе и на ноуте по одному разу. Из облачного веб-чата это сделать
нельзя — он не видит локальный диск.

**Шаг 0 — подстраховка (на машине со свежей работой, до всего).** Сделать «финиш»: закоммитить +
`git push`. Проверить `git status` = чисто и «up to date with origin». Тогда переклон ниже ничего
не потеряет — всё свежее уже на GitHub.

**Шаг 1 — выбрать место ВНЕ Яндекс.Диска** для папки кода (например `C:\Work\`). Внутри области,
которую синхронизирует Яндекс, код лежать не должен.

**Шаг 2 — клонировать с именем машины** (адрес — GitVerse, основной):
```
git clone ssh://git@gitverse.ru:2222/k.s.hromin/furniture-configurator.git config_comp   (на компе)
git clone ssh://git@gitverse.ru:2222/k.s.hromin/furniture-configurator.git config_nout   (на ноуте)
```
Обычный клон, `.git` внутри папки — раз она вне Яндекса, это безопасно, `--separate-git-dir` не нужен.

**Шаг 3 — задать локальные user.name/email** в новом клоне (как ниже в этом файле).

**Шаг 4 — поправить запускалки/пути**, которые ссылались на старую `Config\config` (батники,
`.claude/launch.json`), на новое имя папки. Dev-server раздаёт ту папку, где стартует.

**Шаг 5 — убрать старую папку кода** — только ПОСЛЕ проверки, что новый клон работает (сайт
открывается, `pull`/`push` ходят). Материалы (`Config` без кода) остаются на Яндексе как есть.

**Шаг 6 — в начале сессий** подключать папку материалов через `/add-dir`, когда нужны файлы
(ассортимент, выгрузки, задания).

## Как сменить адрес репозитория на уже настроенной машине

История никуда не денется — меняется только адрес, куда ходить:

```
git remote rename origin github
git remote add origin ssh://git@gitverse.ru:2222/k.s.hromin/furniture-configurator.git
git push -u origin main
```

Прежний адрес переименовывается в `github` (зеркало для Pages), основным становится GitVerse.
История никуда не уезжает — меняются только адреса.

**На компе понадобится свой SSH-ключ**: `ssh-keygen -t ed25519 -C "khrom-comp"`, открытую половину
(`~/.ssh/id_ed25519.pub`) добавить в профиль GitVerse. Закрытый ключ между машинами не копируют —
у каждой свой, так проще отозвать.

## Если садишься за второй компьютер первый раз после этого перехода

Проверь на этом компьютере, подключён ли уже локальный git-репозиторий к GitHub:

```
cd путь\до\Config
git remote -v
```

**Если `git remote -v` ничего не показал** (или ругается «not a git repository» — тогда сначала `cd` в правильную папку) — значит этот компьютер ещё не знает про GitHub. Подключи и подтяни актуальный код:

```
git remote add origin https://github.com/kshromin/furniture-configurator.git
git fetch origin
git branch -M main
git reset --hard origin/main
```

⚠️ `git reset --hard` **сотрёт** любые локальные незакоммиченные изменения на этом компьютере и заменит историю той, что на GitHub. Перед этим стоит проверить `git status` и `git log --oneline -5` — если там есть что-то новое, чего не было на другом компьютере (например, кто-то тут уже работал с Claude до перехода на GitHub), **сначала разберись, что это, и сохрани при необходимости** (спроси Claude — покажи ему `git status`/`git diff`, прежде чем стирать).

При первом `git push` или `git pull` через HTTPS откроется окно входа в GitHub в браузере — войди под аккаунтом `kshromin`, дальше вход будет запоминаться.

## Если git внезапно «не видит» ни одного коммита (все файлы untracked)

Случилось 21.07.2026 при смене компьютера: YandexDisk синхронизирует папку целиком, включая
`.git`, и при переносе состояния с другого компьютера потерял файл `.git/refs/heads/main` и
испортил индекс — `git status` показывал ВСЕ файлы проекта как неотслеживаемые, `git log` — «ветка
main не имеет коммитов». Сами данные (объекты, история) при этом целы.

Починка (без потери файлов, ничего не удалять и не клонировать заново):

1. `tail .git/logs/HEAD` — последняя строка, второй хеш = последний коммит (вершина ветки).
2. `git update-ref refs/heads/main <этот-хеш>` — вернуть ветку на место.
3. `git reset` (БЕЗ `--hard`!) — перестроить индекс от восстановленного HEAD, рабочие файлы не
   трогаются.
4. `git fsck --no-dangling` — убедиться, что база цела; `git status` теперь показывает только
   реальные изменения.

После этого стоит проверить `git diff`: рабочие файлы могли приехать с другого компьютера
**новее** восстановленного коммита (незакоммиченная там работа) — это нормальные правки, их
надо разобрать и закоммитить, а не откатывать.

## База git вынесена из синхронизируемой папки (с 21.07.2026)

На этом компьютере выполнено `git init --separate-git-dir="C:\Users\user\ConfigGit"`:

- **Файлы проекта** — по-прежнему здесь, в YandexDisk, синхронизируются как обычно.
- **База git** (вся история, ветки, индекс) — в `C:\Users\user\ConfigGit`, ВНЕ YandexDisk.
  Файловая синхронизация больше физически не может её испортить.
- В папке проекта вместо каталога `.git` теперь маленький файл `.git` с одной строкой
  `gitdir: C:/Users/user/ConfigGit` — это указатель, git работает как раньше, ничего в
  привычных командах не меняется.

**На втором компьютере при первой же работе там нужно сделать то же самое:**

1. Удалить старый каталог `.git` в папке проекта (вся история и так на GitHub и на первом
   компьютере). Если из синка приехал файл `.git` (указатель с первого компьютера) или его
   конфликтные копии — удалить и их.
2. В папке проекта:
   ```
   git init --separate-git-dir="C:\Users\<имя-пользователя>\ConfigGit"
   git remote add origin https://github.com/kshromin/furniture-configurator.git
   git fetch origin
   git branch -M main
   git reset origin/main
   ```
   (`git reset` без `--hard` — база восстановится с GitHub, рабочие файлы не трогаются;
   `git status` после этого покажет только реальные локальные отличия от GitHub, если есть.)
3. Дальше обычный цикл `git pull` / `git push` — код по-прежнему ездит через GitHub, YandexDisk
   синхронизирует только файлы проекта.
