# Размеры дверей-купе: состояние работ

Этот скилл — **память о ходе работ**, а не справочник. Числа и формулы живут
отдельно, в скилле [premial](../premial/SKILL.md); здесь только план, решения и
границы.

## Что делаем и зачем

Конфигуратор сейчас считает двери по собственным упрощённым константам, которые
расходятся с каталогом производителя. Цель — чтобы размеры дверей, профилей и
наполнения совпадали с тем, что реально придёт от поставщика.

**Этап 1 (текущий).** Подправить под каталог PML то, что уже есть в
конфигураторе: размеры дверей, профилей, наполнения и палитры цветов для пяти
заведённых профилей.

**Этап 2 (по команде пользователя).** Добавлять другие профили из каталога PML,
затем других производителей.

## Жёсткие правила

- **В конфигуратор не лезть без прямой команды.** Указание пользователя
  (сессия 74): «пока правки никакие не делай, готовим только правила»,
  «в конфиг не лезь, только можешь смотреть, изменять ничего нельзя». Читать код
  можно и нужно; менять — только когда скажет.
- **Числа не по памяти.** Любой размер — из каталога, через скилл `premial`.
  Если каталог молчит — так и сказать, а не вывести правдоподобное.
- **Коммитить только своими путями.** В этом репозитории параллельно работают
  другие сессии. `git add -A` затягивает чужие незакоммиченные правки в твой
  коммит — перечисляй файлы явно.

## Соответствие профилей

Установлено по исходникам иконок селектора (`Ассортимент/купе/*.jpg` на Яндексе).
Пять кнопок — это **три разные системы** с разными формулами и разными пределами.

| id | В конфигураторе | В каталоге | Система |
|---|---|---|---|
| `open` | Открытый | Furnial Classic | Furnial |
| `closed` | Закрытый | Furnial Omega | Furnial |
| `slim` | Узкий | FISH | Elephant |
| `slimbox` | Узкий BOX | CAT | Elephant |
| `widebox` | Широкий BOX | П | Premial |

## Найденные расхождения (этап 1, к исправлению)

Всё выявлено чтением кода, **ничего не исправлено**.

| Где | Сейчас | По каталогу |
|---|---|---|
| `wardrobe-constants.js` → `DOOR_OVERLAP` | 30 на все профили | 25 / 31 / 13 / 13 / 60 |
| `wardrobe-constants.js` → `DOOR_MIN_W` / `DOOR_MAX_W` | 500 / 1100 на все | Furnial 550–900, Elephant и Premial 550–1200 |
| `materials.json` → `slidingDoor.profiles[].frameWidth` | 30 / 40 / 20 / 26 / 60 | 25 / 31 / 13 / 13 / 60 — совпадает только `widebox` |
| `materials.json` → `slidingDoor.colors` | один набор из 5 цветов на все профили | палитры 4–12 и разные по составу |
| высота двери | считается от высот рельсов в 3D | `HD = HO − 36` (Furnial) или `− 40` (Elephant, Premial) |
| ширина двери | формула продублирована в `wardrobe-geometry.js` и `wardrobe-sizing.js` | должна быть одна |
| наполнение | не считается вовсе | `HF`/`WF`, отдельно ЛДСП и зеркало |

**Цвета — самое грубое расхождение.** По трём профилям из пяти конфигуратор даёт
выбрать цвет, которого у профиля не существует: у Закрытого нет Чёрного и
Золота, у Узкого и Узкого BOX нет Бронзы, у Широкого BOX нет Золота и Бронзы.
Матрицы доступности — в `premial/references/dekory.md`.

Насколько врут размеры: проём 2400 мм, три двери — сейчас 820 мм для любого
профиля, по каталогу 809 / 817 / 821 / 840. До 20 мм на дверь, в разные стороны.

## Открытые вопросы

Требуют замера или запроса производителю, расчётом не берутся:

1. **Многосекционные двери** — сколько высоты съедает разделительный профиль.
   Сечения известны (28 мм со стяжкой, 19.2 мм без, паз 10.1 мм), глубина
   посадки наполнения в паз — нет. В `door-profiles.js` функция
   `splitFillHeights` намеренно возвращает `null`, пока не замерено.
2. **`LMh`** (длина разделителя) для Furnial, Elephant, Premial. Для систем Felix
   каталог задаёт `LMh = LPh + 2`; для этих трёх — молчание.
3. **Допуски на рез и кромку** — каталог даёт чистовой размер детали.

## Журнал решений

- **Модуль вместо документа.** Инструкцию для кода решено оформлять как источник
  чисел (`door-profiles.js`), а не как текст: текст программист перепечатает в
  константы руками, и числа разойдутся с каталогом.
- **Производитель — верхний уровень.** Реестр формул сгруппирован
  производитель → система → позиция, чтобы второй производитель добавлялся новым
  разделом. Соответствие названиям конфигуратора держится ОТДЕЛЬНО: при двух
  производителях с профилем «П» иначе не понять, чей он.
- **Формулы других производителей не подгонять под PML.** Если модель другая
  (ширина через зазор, а не через перекрытие) — описывать как есть.
- **`QO = QD − 1`** в классической раздвижной раскладке — ровно то, что уже
  заложено в `buildDoorRow`. Исключение: Aluforce Adjust на 4 двери, там
  внутренние двери сходятся встык и `QO = 2`.

## Что сделать следующим шагом

Когда пользователь даст команду на этап 1 — порядок такой, от безопасного к
рискованному:

1. Палитры цветов по профилям в `materials.json` (данные, 3D не трогает).
2. `frameWidth` профилей там же.
3. Подключить `door-profiles.js` к `wardrobe-sizing.js` — убрать `DOOR_OVERLAP`
   и `DOOR_MIN_W`/`DOOR_MAX_W`.
4. То же в `wardrobe-geometry.js`, чтобы формула ширины осталась одна.
5. Высота двери и размеры наполнения.

Перед началом — проверить, не идут ли в `js/` правки параллельной сессии.
