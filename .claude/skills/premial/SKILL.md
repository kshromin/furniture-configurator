# Системы Premial Aluminium Systems (PML)

Справочник по техническому каталогу PML 2026 (164 стр.). Здесь — данные, которые
нельзя выдумывать: формулы, допуски, длины профилей, доступность декоров.

**Главное правило: цифры не по памяти.** Формулы у разных профилей отличаются на
единицы миллиметров, и на глаз они выглядят одинаково. Всегда открывай нужный
файл в `references/` и цитируй оттуда. Если данных нет — скажи, что нет, и предложи
посмотреть исходный каталог (см. «Работа с исходным каталогом»).

## Пять профилей конфигуратора

В конфигураторе этого проекта профили названы по-своему. Это **три разные
системы** с разными формулами и разными предельными размерами:

| В конфигураторе | В каталоге | Система |
|---|---|---|
| Открытый | Furnial Classic | Furnial |
| Закрытый | Furnial Omega | Furnial |
| Узкий | FISH | Elephant |
| Узкий BOX | CAT | Elephant |
| Широкий BOX | П | Premial |

Пошаговый расчёт по ним — [raschet-dverey.md](references/raschet-dverey.md):
дверь → профили → наполнение, с проверкой пределов, расходом палок и примером.
Если вопрос про расчёт именно этих пяти — иди сразу туда.

## Общие обозначения

Единые по всему каталогу, все размеры в мм:

| | | | |
|---|---|---|---|
| `HO` | высота проёма | `WO` | ширина проёма |
| `HD` | высота двери | `WD` | ширина двери |
| `HF` | высота наполнения | `WF` | ширина наполнения |
| `LPh` | длина горизонтальных профилей | `LPv` | длина вертикального профиля |
| `LMh` | длина двустороннего (разделительного) профиля | `LO` | длина вертикальной декоративной накладки |
| `NL` | длина направляющих | `QD` | количество дверей, шт |
| `QO` | количество мест перекрытий дверей, шт | `WZ` | ширина перекрытия дверей |
| `WPv` | ширина вертикального профиля | `TF` | толщина наполнения/фасада |

`QO` — количество мест, где двери **накладываются друг на друга в плане**. Это
свойство раскладки, а не производная от `QD`. В классической раздвижной схеме,
где перекрывается каждая соседняя пара, `QO = QD − 1`. Но не всегда: у навесной
Aluforce Adjust на 4 двери перекрытий **два, а не три** — две внутренние двери
сходятся встык (каталог стр. 58, PDF 60). Считай по плану раскладки.

Отдельные наборы обозначений у корпуса Aluforce Adjust (`SO/SI/DT/DC/DB/HB/SM`)
и у Con Bisagras (`WH/HC/TS/TC`) — они описаны в своих файлах.

## Как отвечать на типовые вопросы

**«Посчитай двери на проём X×Y»** — нужны четыре вещи: система, профиль, число
дверей и число мест перекрытий. Без профиля расчёт невозможен: у Premial восемь
вертикальных профилей и у каждого своя формула ширины. Дальше — по цепочке
`HD → WD → LPh → NL → HF/WF`, отдельно для ЛДСП и для зеркала/стекла (у них
разные вычеты, потому что разная толщина и уплотнитель). Результат давай с
проверкой на предельные размеры системы.

**«Какой профиль выбрать»** — смотри на тип наполнения и на бюджет. Асимметричные
(C, Q, L, Furnial Classic) — классика купе, ручка образуется самим профилем.
Симметричные (A, I, П, H) — «рамка» с обеих сторон, узкий A и профиль I с каналом
под кромку идут и в подвесные Felix Hilaris. Elephant — когда нужна тонкая видимая
рамка 13 мм.

**«Есть ли такой цвет на такой профиль»** — только по таблицам из
[dekory.md](references/dekory.md). Палитра общая, но доступность у каждого профиля
своя: например, блестящие декоры есть почти только на C Classic, а Латунь браш из
подвесной линейки — только на профиле I.

**Пересчёт под конфигуратор** — формулы каталога дают размер детали, а не размер
заготовки. Если задача про раскрой или экспорт в программу — предупреди, что
допуски на рез и на кромку каталог не закладывает.

## Работа с исходным каталогом

Исходник: `<Яндекс.Диск>/Config/Ассортимент/купе/Premial-Aluminium-Systems-Технический-каталог-2026.pdf`
(папка материалов подключается через `/add-dir`, см. корневой `CLAUDE.md`).

Три особенности, из-за которых обычное чтение PDF даёт мусор:

1. **Шрифты подгружены без ToUnicode.** Прямая выдача текста — нечитаемая каша
   («ǎǕǒǗǊ»), а цифры вообще пропадают (они попадают в управляющие символы).
   Используй `scripts/catalog.py text` — там разобранная кодировка.
2. **Размеры на чертежах часто повёрнуты**, поэтому в тексте выглядят
   перевёрнутыми: `042` — это 240, `01` — это 10, `SOMSOC` — это COSMOS. Числа с
   чертежей без проверки картинкой брать нельзя.
3. **Схемы сборки, сечения и присадки — векторная графика без текста.** Их
   невозможно прочитать текстом, нужен рендер страницы: `scripts/catalog.py render N`.

Нумерация: **страница PDF = страница каталога + 2** (стр. 16 каталога = 18-я PDF).
Скрипт принимает номера страниц PDF.

```bash
python .claude/skills/premial/scripts/catalog.py text 13-15
```

Точки в таблицах соответствия декоров — тоже векторные кружки, а не текст;
`scripts/catalog.py matrix N` восстанавливает такую таблицу в виде сетки. Готовые
результаты уже перенесены в [dekory.md](references/dekory.md), скрипт нужен, только
если проверяешь спорную клетку или каталог обновился.
